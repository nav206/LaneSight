# Design: LaneSight citywide always-route + designated-lane trust MVP

## Problem Statement

Google Maps and Lyft Bikes can return A→B bike routes across SF, but riders often lack confidence: they cannot see how much of the trip is real designated green infrastructure vs taking space on ordinary streets, or get clear heads-ups when facility class changes mid-route. LaneSight should be a fully shippable, portfolio-grade SF bike planner that always returns a citywide route and makes that cyclist-POV truth legible — for daily dogfooding and for demos to Lyft HR / recruiters / seniors. No placeholders.

## What Makes This Cool

Honest coverage: **% designated bike facilities** plus **color on every segment**, so you know when the lane disappears and you must take extra caution. Transition callouts on the map and in the ordered **heads-up list** (MVP stand-in for turn-by-turn instructions; never reject the route). Compare alternatives by exposure vs time when two distinct candidates exist. The “whoa” is anticipating protection changes — not another blue line.

## Constraints

- SF-only for MVP; official SFMTA Class I / II / IV inventory is designated-lane source of truth (not ML).
- Primary users are **mobile**; desktop is secondary.
- Reuse existing Express + OpenAPI/Orval + Leaflet stack; no auth/DB/payments.
- Do not present street connectors as official bike lanes.
- Elevation, potholes/condition depth, voice nav, community flags + points = later layers.
- No silent fallback that hides facility class.

## Premises

1. MVP = citywide **always-route** + designated-lane **%** + **color-coded** geometry + **up to two comparable alternatives when distinct** (always ≥1 attributed route) + mobile-first UI (map gestures, distinct A/B markers). Deeper annotations / voice / community later.
2. Stop rejecting routes that are not continuous on the SFMTA graph; ordinary street / connectors OK if clearly marked non-designated.
3. SFMTA inventory defines “designated”; API exposes **source + freshness** (not implied live ground truth).
4. Routing + API expose **segment-level facility type** (and transitions) so UI can color, compute %, and list heads-ups.
5. This design scopes routing + API + the trust UI needed to ship the MVP; polish iterations follow.

## Recommended Approach

**Approach A.** Wireframe (repo): `docs/designs/lanesight-routing-trust-mvp-sketch.html` (also state-root sketch `403na-main-sketch-20261103-235759.*`). Mobile bottom sheet + map; compare cards.

### Facility mapping & designated % (committed)

| SFMTA / match result | `facility` | `designated` | Counts toward % |
|---|---|---|---|
| CLASS I, or raised / physically protected Class IV | `protected` | true | yes |
| CLASS II or CLASS IV (buffered/painted, not raised) | `bike_lane` | true | yes |
| CLASS III / sharrow-only / shared markings | `shared` | false | **no** |
| No SFMTA match (or direction mismatch) | `ordinary` | false | no |

**Formula:** `designatedPercent = 100 * sum(segment.distanceMeters where designated) / sum(all segment.distanceMeters)` (0 if total distance is 0).  
**Unmatched rule:** unmatched geometry is always `ordinary` / `source: unmatched` — never paint designated green.

### Spatial matching (committed defaults)

- Max lateral offset: **25 m** to nearest eligible directed SFMTA centerline.
- Require travel direction compatibility with SFMTA `direct` / `dir` when resolvable; else treat as unmatched.
- Split a new segment whenever facility class changes or continuous unmatched gap exceeds **15 m**.
- Fixtures (must assert labels / % bounds in tests): (1) Civic Center → Ferry baseline, (2) OD crossing Fell leftmost-lane transition, (3) parallel-road false-positive trap, (4) short gap &lt;15 m should not flip class spuriously.

### Alternatives strategy (committed)

- **One response shape:** `POST /api/lanesight/route` returns `{ selectedIndex, routes: BikeRouteResponse[] }` with **2** entries when possible.
- Produce candidates: (1) BRouter `fastbike-verylowtraffic` (label **Faster**), (2) same OD with a via biased onto dense SFMTA corridors **or** a second BRouter profile favoring bike infrastructure; then **re-rank/label** so card **More lanes** = higher `designatedPercent`, **Faster** = lower `durationSeconds`.
- **Distinctness:** keep two cards only if geometry Jaccard overlap of sampled points &lt; **0.85** **or** `|Δ designatedPercent| ≥ 5` **or** `|Δ durationSeconds| ≥ 120`. Else return **one** route, `routes.length === 1`, UI hides compare row (success criteria: always ≥1 route; show compare when ≥2 distinct).
- **Jaccard sampling:** densify each route polyline to points every **25 m** along the geodesic (WGS84); snap each point by **rounding latitude and longitude to 4 decimal places** (~11 m at SF latitudes; lon spacing is slightly coarser than lat); Jaccard = `|A∩B| / |A∪B|` over those snapped cells. Same algorithm server-side for the distinctness gate and in fixtures.
- **Server ordering (committed):** when two distinct routes exist, label **More lanes** = higher `designatedPercent`, **Faster** = lower `durationSeconds`. Place More lanes at `routes[0]` and Faster at `routes[1]`; set `selectedIndex: 0`. **If `designatedPercent` ties:** keep both only if duration still differs by ≥120s — then `routes[0]` = longer (still labeled More lanes / default select), `routes[1]` = shorter (Faster); if duration also ties (or labels would attach to the same candidate), **collapse to one route**. When only one route, `routes[0]` + `selectedIndex: 0`. Client may change selection locally; initial paint follows server `selectedIndex`.

### API / routing

1. Replace reject-on-disconnected-graph with **BRouter full bicycle route** (reuse existing BRouter client; primary profile `fastbike-verylowtraffic`).
2. Attribute geometry per matching rules above; emit `segments` + `transitions`.
3. OpenAPI: wrap response as `{ selectedIndex, routes[] }` where each route includes:
   - `summary`: `designatedPercent`, `mixedTrafficMeters`, `transitionCount`, `networkUpdatedAt`, distances/durations, `label`
   - `segments[]`, `transitions[]` as above (`source`: `sfmta` | `unmatched`)
4. **BRouter / upstream failure:** if geocode OK but BRouter times out / 5xx / empty geometry → **502** with `{ error }` (same family as today); **no** silent street-only polyline without facility attribution. Client shows retry. Partial routes are not returned.
5. Fixtures + codegen Zod / React Query.

### UI (mobile-first)

- Full-bleed Leaflet map: pinch zoom, pan, two-finger rotate where supported; distinct **A / B** markers.
- Bottom sheet: trust % for selected route, compare cards (when `routes.length ≥ 2`), **heads-up list = MVP “instruction list”** (transition warnings in order along the route — not spoken turn-by-turn), legend.
- Color polyline by segment facility; pin callouts at transitions (same text as heads-up entries).
- **Legacy layers:** Bay Wheels + street conditions remain **optional map toggles** (default on desktop as today; default collapsed/off-map clutter on mobile so trust/compare stays primary).
- Desktop: widen sheet to side pane without changing API contract.

- Any reasonable SF A→B returns ≥1 attributed route (no “no mapped bikeway” hard fail for ordinary gaps).
- Response includes designated % (per committed formula) and segment colors verifiable on Civic Center → Ferry.
- When two distinct candidates exist, compare cards work; map updates on select; mobile usable one-handed.
- Source freshness visible; transitions in heads-up + map pins; BRouter failure is explicit 502 + retry.
- Typecheck/build green; OpenAPI clients regenerated.

### R3-1 — consistency (blocking)

**Problem**

> When two distinct routes tie on `designatedPercent`, the More-lanes tie-break assigns `routes[0]` to the route with lower `durationSeconds`, while the re-rank rule assigns the Faster label to the route with lower `durationSeconds` and requires `routes[1]` to be the other candidate; that other route cannot simultaneously have lower duration and be the slower tie-break loser.

**Remedy**

> Define tie behavior explicitly: e.g. when `designatedPercent` ties, order by duration (faster at index 1 as Faster card) while index 0 remains More-lanes default selection, or collapse to one route when metric labels would coincide on the same geometry; document the chosen rule so `routes[]` order, card labels, and `selectedIndex` stay aligned.

### R3-2 — clarity (minor)

**Problem**

> The grid snap is described as "4 decimal degrees" lat/lon, which reads as degrees of arc rather than fixed-precision rounding (~0.0001° ≈ 11 m at SF latitudes) and can mislead implementers.

**Remedy**

> Replace with explicit snap rule (e.g. round lat/lon to four decimal places, or state meter-based grid with WGS84 geodesic cell size) and note lon/lon spacing difference at SF latitude if relevant.
